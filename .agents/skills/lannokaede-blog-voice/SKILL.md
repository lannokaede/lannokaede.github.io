# lannokaede 个人博客写作风格指南

文章定位是**精简的技术记录**：只写配置、实现、问题、排查和验证结果，不加戏、不写情绪铺垫、不编日常场景。

## 1. 标题与正文原则

- **标题要短**：直接点出做了什么任务即可，不把细节全塞进标题（例如 `LibreChat 自建 AI 聊天站`、`VPS 自建代理与 DNS 排查`）。
- **正文只要技术相关**：直奔架构、配置、现象、原因、改法、命令和已测/未测结论；去掉背景闲聊、心理活动、过渡废话和收尾感叹。
- **结构清晰紧凑**：善用短段和要点列表，少说废话，能两句话说清的绝不写一段。
- **文章保持独立**：不同文章之间少做强行联动或互链，除非有直接的技术前置依赖。
- **模糊处理第三方平台**：涉及第三方中转 API、代理商或私人线路时，不写具体平台名，用「第三方 API」「中转线路」等泛称带过即可。

## 2. 明确规避的表达

1. **禁止刻意装口语**：不用“折腾”“顺手”“顺带”“搓了个”“干脆”“凑合”“破案了”“老老实实”“顺风顺水”“乖乖等”。
2. **禁止公文 / 播音腔**：不用“总而言之”“值得一提的是”“希望这篇对你有帮助”“实际用的时候发现一个挺现实的问题”。
3. **禁止加戏**：不要为了凑故事感补写动机、吐槽或心理描写。

## 3. 事实边界

- 不编造未提供的版本号、数据、时间线或测试结果。
- 跑通的写跑通，未测的明确标注未测。
- 保留代码块、命令、路径、URL、版本号和 frontmatter 准确。
