给大肥鱼补视频识别的时候，翻了一下传给模型的消息：群里发的是一段视频，处理完只剩下“[视频]”几个字。有些路径拿到了文件地址，也没有继续提取画面。之前觉得她对视频的评价不着边际，查到这里才知道，模型根本没收到那些内容。

我想让她在群里能跟着视频说两句，平时大家聊天，也能偶尔插句话。大肥鱼是放在 QQ 里的聊天角色，人设参考了社区的[大肥鱼人格文件](https://github.com/whyever77/dafeiyu-astrbot/blob/main/persona/大肥鱼-人格.md)。底下用 AstrBot 和 NapCat，后来陆续补了群聊判断、表情包和长期记忆。

## QQ 接入和模型

这台服务器跑 OpenCloudOS 9.4，两个主要容器是 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 和 NapCat。NapCat 登录 QQ，通过 OneBot 11 反向 WebSocket 把消息交给 AstrBot；AstrBot 处理消息、调用模型，再把回复传回去。

目前固定在 AstrBot v4.29.1 和 NapCat v4.18.41，镜像固定了 digest。升级前一起备份 Compose、AstrBot 数据和 QQ 登录目录，回退时也用原来的镜像。登录数据要保留，否则还得重新扫码。

聊天模型没有部署在这台机器上，AstrBot 连接已有的 OpenAI 兼容网关，聊天和记忆整理用 DeepSeek。本机跑的是消息接入、插件，以及后面会提到的小型向量服务。

管理面板经 Nginx 提供 HTTPS 访问，后端端口绑定回环地址。日常维护主要在 `/opt/astrbot` 下：

```bash
docker compose ps
docker compose logs --tail 100 astrbot
docker logs --tail 100 napcat
```

## 群聊回复和人设要一起改

最初用 AstrBot 自带的随机搭话，概率设为 15%。后来装了 [Chat Plus](https://github.com/Him666233/astrbot_plugin_group_chat_plus)，把群聊回复判断交给它，初始概率仍是 0.15，原来的随机触发则关掉。

私聊仍走 AstrBot 原来的流程。群聊交给 Chat Plus，带上最近 30 条群消息，对话上下文最多 20 轮，主要是想让她能接住前面连着发的几句话。

换大肥鱼人设时，有两个地方需要同步：AstrBot 的默认人格，以及 Chat Plus 使用的人格。只改默认人格，群聊那边仍可能继续用旧角色。

我对人设改得比较多的是说话方式。普通闲聊尽量一到三句，不要先复述问题，也不要求每句话都带“唔”“哼”。有些语气偶尔出现还好，写成固定要求之后，几轮下来全是一个腔调。

社区人设里的能力也没有全照搬。语音和生图没接，相关描述就按当前情况改掉。群聊称呼按发言人的身份区分，不把每个搭话的人都叫成同一个称呼。

## 表情包先碰到了接口问题

表情包用 meme_manager，先导入一小套图库，给图片补了描述和向量。选图时参考近期对话和当前人设，一次最多发一个。自动收集只在指定群里开，设了采样、冷却和去重，避免把群里的图片全部存下来。

图片发送用了 Base64。AstrBot 和 NapCat 在两个容器里，前者看得见的文件路径，后者不一定能打开。

选图时还遇到了模型接口的兼容问题。插件请求强制调用工具，网关不支持对应参数，直接返回错误。针对这个错误补了处理，走插件已有的 JSON 回退方式。

补丁留在插件目录之外，附了回归测试。升级 meme_manager 时还要重新检查这处，否则插件一更新，手工改过的部分可能就没了。

## 记忆接口的长度限制

长期记忆装的是 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)。聊天模型负责整理内容，相关记录的检索用向量。本地 CPU 跑 `BAAI/bge-small-zh-v1.5`，输出 512 维向量，接口只监听回环地址。

刚接上时，写入、召回和会话隔离都测过。后来处理较长的记录，却被本地向量接口拒了。

原因是两边的长度限制对不上：接口最多接收 2000 字符，LivingMemory 聚合出来的文本可以到 4000 字符。短文本测试没有碰到这条限制。

接口上限改成 4000 字符后，中文长文本和批量请求不再被拒。不过模型仍按 512 tokens 截断，长记录后面的内容可能根本没参与向量计算。较长的记忆记录还得考虑怎么切分。

## Chat Plus 和视频识别

视频这部分用的是 [LLM 综合增强](https://github.com/Foolllll-J/astrbot_plugin_llm_enhancement)的媒体模块，另外做了精简入口。普通视频、引用消息里的视频、合并转发里的视频，都从这里提取，再交给 FFmpeg 抽帧。

精简入口只补媒体内容，普通文字消息直接跳过，聊天是否触发仍由 Chat Plus 管。

这里又碰到了插件执行顺序：Chat Plus 在回复前会重写请求。视频信息如果加在它前面，最后给模型的请求里仍可能丢掉这一段。因此把媒体处理放到重写之后，保留原来的人设和用户问题，再补上视频理解结果。

回复要求也改成了日常评价。有人发一个梗视频，她能针对画面里的动作、反差接一句就够了，不需要列主题和内容提要。识别结果只是回复时用的材料。

测试用 FFmpeg 生成了一段八秒短片，红球向蓝方块靠近。直接发送、引用和合并转发三条路径都调用了真实模型，回复里能提到这两个物体和它们的动作。

现在依据的是抽帧和画面文字，没有接语音识别。读视频有总超时，失败时会把失败情况告诉回复模型，要求它别编画面。

## QQ 仍然会掉登录

前面大部分测试都能在服务器上做，QQ 收发还得另算。

之前手机扫过码，服务器也收到了扫码事件，随后 QQ 却返回了错误码 168，提示账号存在安全限制。另一次是保存的登录身份失效，快捷登录被拒，只能重新扫码。两种情况都遇到过，不能只看容器是不是还在运行。

10 月 28 日安装视频插件后的检查里，QQ 又停在等待扫码。插件已经加载，服务端的短片测试也通过了，但这几次没有向群里发测试消息。重新登录后，还要在 QQ 里分别试普通视频、引用追问和带视频的合并转发，特别是群里压缩过的画面，和生成的测试短片会有多少差别。
