最近在服务器上养了条大肥鱼。

名字叫大肥鱼，设定其实是蓝色的小鲸鱼娘。平时在 QQ 里聊天、吐槽，偶尔发个表情包。我想让她在群里也能接上话，看到别人发的视频能评论两句，不用每次都先 @ 她。

现在用的是 AstrBot + NapCat。最初先把文字聊天接通，后面陆续加了表情包、记忆和视频识别。配置改过几轮，记一下目前这套和遇到的问题。

## 先把 QQ 和模型接起来

服务器系统是 OpenCloudOS 9.4，AstrBot 和 NapCat 都用 Docker 跑。目前固定在 AstrBot v4.29.1、NapCat v4.18.41，镜像也固定了 digest，升级前留备份。

NapCat 负责登录 QQ，通过 OneBot 11 的反向 WebSocket 接入 AstrBot。AstrBot 收到消息后调用模型，再把回复交给 NapCat 发回去。

```text
QQ 消息 → NapCat → AstrBot → 模型接口
                  ↑            ↓
                  └── 回复 ────┘
```

模型接的是已有的 OpenAI 兼容网关，聊天和记忆整理用 DeepSeek。这里的模型接口跑在别的服务上，这台机器主要负责 QQ 接入、插件和数据存储，没有在本机跑聊天大模型。

AstrBot 的数据目录挂载到宿主机，升级容器时保留。管理面板通过 Nginx 提供 HTTPS 访问，后端端口只绑定回环地址。

日常查状态主要用这些：

```bash
cd /opt/astrbot
docker compose ps
docker compose logs --tail 100 astrbot
docker logs --tail 100 napcat
```

AstrBot 的安装和平台接入可以从[项目文档](https://github.com/AstrBotDevs/AstrBot)看起。这篇记录的是我这台机器上的配置，没有贴密钥、QQ 号码和面板地址。

## 换成大肥鱼的人设

之前用的是另一个角色，后来换成了大肥鱼。人设参考了社区的[大肥鱼人格文件](https://github.com/whyever77/dafeiyu-astrbot/blob/main/persona/大肥鱼-人格.md)，再按已经装好的功能做了调整。

我比较在意回复的长度。普通闲聊一到三句就行，能接上当前话题，不要每次都先复述一遍问题，再写一段解释。也没要求每句话都带语气词，不然聊几轮就会觉得一直在重复同一个句式。

还有些设定得和程序对得上。人设里写“会记住你说的话”，得有记忆插件；写“会看视频”，得真的把画面送给模型。语音和生图目前没接，相关能力就没有按已实现来写。

换人设时除了改 AstrBot 默认人格，也改了 Chat Plus 使用的人格。两个地方都要核对，免得普通对话已经换了角色，群聊插件还在按旧人设回复。

## 群里什么时候说话

只在被 @ 时回复，平时基本看不到她；每条消息都接，又太吵。

一开始用 AstrBot 自带的 15% 随机搭话，后来交给 [Chat Plus](https://github.com/Him666233/astrbot_plugin_group_chat_plus)处理群聊判断，初始概率仍设为 0.15。原来的随机触发关掉，避免两个地方各自判断一次。

这里的 15% 不是群里每发一百条就一定回十五条。实际还要看消息和插件的判断，也有发送限流、任务排队。

群聊会带上近期消息，最近群消息最多 30 条，对话上下文最多 20 轮。这样别人连续发几句时，她有机会知道前面在聊什么。私聊没有交给 Chat Plus 接管。

戳一戳单独装了 PokePro，只保留需要的互动。定时戳人、禁言之类的功能没开。

## 表情包和长期记忆

表情包用的是 meme_manager，起步导入了 27 张、16 个分类。图片补了描述和向量，回复时结合最近两轮对话选图，一次最多发一个。

NapCat 和 AstrBot 在不同容器里，传图片时用了 Base64 输出。否则一个容器里存在的文件路径，另一个容器未必能读到。

自动收集只对选定的群开启，私聊不收。收集有采样、冷却和每日识别上限，也会按哈希去重，避免群里刷一轮图就全存进来。

这里还遇到一次接口兼容问题：插件请求强制调用工具，模型网关不支持这个参数，直接报错。最后补了兼容逻辑，识别到这种错误后，退回插件已有的 JSON 处理方式。这个补丁单独留了文件，以后升级表情插件还得重新检查。

长期记忆用 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)，向量模型是本地 CPU 跑的 `BAAI/bge-small-zh-v1.5`，输出 512 维向量。

记忆检索时，先把文本转成向量，再找相关记录提供给聊天模型。聊天还是走远端接口，本地这个小模型只做向量计算。

刚接上时测过写入、召回和会话隔离。后来发现一处长度不匹配：本地向量服务最多收 2000 字符，记忆插件聚合出来的文本可能有 4000 字符，请求因此被拒。把服务的输入上限对齐到 4000 字符后，又测了中文长文本和批量请求。这只是放宽服务接收长度，模型本身仍会按它的限制截断。

## 转发的视频为什么看不懂

这次补视频功能前，先看了实际传给模型的内容。

合并转发里即使有视频，原来的处理也可能只留下一个“[视频]”。普通视频有时拿到了文件路径，但没有继续抽帧。模型没有看到画面，自然很难评价里面的动作或梗。

后来选了 [LLM 综合增强](https://github.com/Foolllll-J/astrbot_plugin_llm_enhancement)的媒体解析模块，做了一个精简入口。保留视频提取和抽帧，群聊触发继续交给 Chat Plus，避免新插件把唤醒和聊天逻辑也接管过去。

还有执行顺序的问题。Chat Plus 会在回复前重写请求，视频识别需要在它之后把画面理解结果补进去，否则前面提取到了内容，最后生成回复时还是可能丢掉。

这次要的效果很简单：群友转来一个视频，大肥鱼看见画面里的事，顺着聊一两句。没有要求她列出“视频主题、主要内容、核心观点”。

测试时用 FFmpeg 生成了一段八秒短片，画面是红球靠近蓝方块。直接视频、引用视频和合并转发三条路径都跑了真实模型调用，回复能针对画面调侃，没有变成视频摘要。

目前只根据画面和可见文字理解，还没配语音识别。视频读不到时会说明没看清，不按文件名猜剧情。

## 扫码之后还得看登录状态

QQ 登录比装容器麻烦。

之前有一次手机扫了码，服务器也收到了扫码事件，但随后 QQ 返回错误码 168，提示账号存在安全限制。另一次是已经保存的身份失效，快捷登录被拒，需要重新扫码。

所以手机上点了确认之后，还得看 NapCat 的实际登录状态，以及 AstrBot 有没有建立 OneBot 连接。容器显示运行中、管理面板能打开，都不能单独说明 QQ 在线。

写这篇时，视频插件已经加载，三条测试路径也都通过了，但最近一次检查里 QQ 仍在等待重新扫码。真实 QQ 收视频、引用追问和合并转发的收发测试，要等账号重新连上后再补。

暂时先记到这里，等她重新上线，拿群里的实际视频试试。
