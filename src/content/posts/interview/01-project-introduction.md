从 Java、织课到 Go Agent 的经历怎样讲清楚，以及为什么不能只列技术栈。

## Q1：请用一到两分钟做自我介绍

**当时回答（归纳）**

电子科大大三，大一接触 Java 后端，在工作室参与招新网站；大二做织课、学习对象存储和 RAG；暑假开始做 LanAgent，并自学 Go。

### A：时间线清楚，还要补“职责”和“求职落点”

可以按“当前身份与方向 → 两个项目的职责 → 当前学习重点”组织：

> 我是电子科技大学软件工程专业本科生，希望应聘 Go 后端、Agent 应用方向的实习。此前参与过工作室网站开发，在织课项目中主要负责后端和联调；最近独立开发 LanMerchant，把模型工具调用与商家召回业务结合起来。目前重点补充 Go 并发、数据库事务和 Agent 可靠性。

个人年级、实习时间、奖项和具体分工以真实情况为准。不要把参考话术当成新的经历。

## Q2：LanAgent 解决什么问题？一次请求怎样完成？

**当时回答（归纳）**

面向小商家老客召回，做经营分析、客群筛选和优惠方案试算。用户提出“召回 60 天未消费老客，预算 3000 元”，后端校验身份、保存持久任务，固定 worker 认领；分析 Agent 提供经营分析，方案 Agent 调工具试算、保存草案，保存时再检查预算。

### A：把完整业务闭环讲出来

```text
商家目标与可信约束 → 持久任务 → worker 认领
→ 分析 Agent → 方案 Agent 与业务工具 → 保存草案
→ 人工按版本审核发布 → 顾客领券 → 模拟订单核销 → 指标复盘
```

模型负责提出动作，后端工具负责实际执行和规则校验。模型没有直接发布、领券、核销的权限。

**易混淆**：保存草案不是活动已发布；本地模拟订单不是真实支付。LanAgent 是仓库称呼，当前主讲业务是 LanMerchant。

## Q3：为什么第一轮后半段像“死循环”？

**我的反馈**：“你一直在死磕相同的问题。”

### A：这是模拟主持节奏的问题，也要在复习中避免

第一轮围绕领券、事务、幂等不断换条件，明确知识缺口后仍反复教学确认，挤掉了其他简历内容。后续每个主题通常追问两三层，知识缺口确认后记录并切换；集中复习时再做变式练习，不强求当场练熟。

**复测**：不用背稿，90 秒讲清自己的职责、一个真实请求和项目边界。
