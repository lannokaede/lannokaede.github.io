按本轮要求只建立用途概念，重点纠正 HTTPS 隐藏接口和 DNS 等于连接复用的误解。

## Q1：输入 HTTPS 地址，到后端收到请求，经历什么？

**状态：原题后主动要求网络简单过，未完整独立作答。**

### A：以常见 HTTP/1.1、HTTP/2 为例

```text
解析 URL → DNS 获取 IP → TCP 建连 → TLS 握手
→ HTTP 请求 → 网关或后端处理 → HTTP 响应
```

缓存和已有连接可省略部分步骤；HTTP/3 基于 QUIC，不套用 TCP 这一段。这里只建立概念，不深挖握手报文。

---

## Q2：HTTPS 保护什么？是不是隐藏接口？

**当时回答**：更安全，保护后面的字段，不直接展示接口。

### A：保护传输，不把接口从用户眼前藏起来

TLS 提供传输加密、完整性和服务器身份验证。浏览器使用者仍能在开发者工具中看自己的请求。中途观察者一般无法读取加密的路径、参数和正文，但目标 IP、域名等信息不一定隐藏。

保护到 TLS 终止点，例如网关；网关到业务服务若明文 HTTP，该段需另行考虑。HTTPS 不代替登录和权限校验。

---

## Q3：TCP 与 UDP 的区别？

**当时回答正确到核心**：可靠面向连接，对比不可靠无连接。

TCP 提供有序可靠字节流、重传等机制，但故障时仍会失败；UDP 按数据报发送，本身不保证到达、顺序和去重，应用可在其上建立可靠协议。不能简单认为 UDP 在所有业务都一定更快。

---

## Q4：为什么连续模型调用要复用连接？

**当时回答**：同一域名会解析到具体 IP。

### A：DNS 缓存不等于连接池

同域名是可能复用的前提之一，收益在于减少重复 TCP/TLS 建连的时间与资源。DNS 缓存保存域名解析，连接池维护可复用连接。具体复用还受协议、请求状态及客户端配置影响。

**复测**：说清 DNS 找地址、TCP 传数据、TLS 保护传输、HTTP 表达请求四个角色即可。
