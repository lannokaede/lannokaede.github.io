## Q1：★ 一次工具调用怎样从模型走到业务代码？

应用提供工具名、描述和参数结构；模型返回调用意图；后端按工具名查注册表，解析、校验并执行，再把结果交回模型。

**调用 ID 关联结果，工具名选择函数，不能只凭 ID 分发。** JSON 合法也不等于允许执行，还要检查身份、归属、参数和业务规则。未知工具、非法参数不得执行，可在受控轮次内反馈模型修正。

---

## Q2：△ 预算为什么必须由后端检查？

模型可以提出方案，但无权改变可信预算。后端保存结构化整数金额，工具保存草案时重新校验数量、面额、溢出和预算，跳过试算也不能绕过。

**我的疑问**：“是不是一定要单独字段？还有更好方案吗？”

关键不在输入框，而在最终有可信约束。预算可以由用户确认自然语言提取结果，也可来自配置或审批。多个活动共享总预算时，还需预占机制；只在聊天中写“预算 3000”不会自动形成硬保证。

---

## Q3：★ SSE 为什么不能每次 Read 就直接解析？

**网络读取、SSE 事件、工具参数，是三层边界。** 一次读取可能含半条或多条事件；完整事件也可能只承载半段工具参数。

先按协议缓冲分帧，再按调用索引累积参数，确认正常结束、解析校验后执行；不能按自然语言“完整句子”拼接。超限或断流应失败，不把截断 JSON 交给工具。

**当时误区**：认为每片都有 ID；实际当前兼容流主要按 `index` 重组，ID、名称可能只在早期片段出现。

## Q4：△ 双 Agent 与框架到底带来什么？

分析 Agent 只读，方案 Agent 制定方案，主要收益是职责与权限清楚；串行多调用不保证更快、更省 token。

LangGraphGo 组织模型、工具节点和条件路由，当前简单循环手写也可以。业务校验、持久队列、幂等仍靠后端代码，不能把框架所有能力算成已实现。

独立查询可考虑并发，有依赖或副作用冲突则串行。**同轮保存参数已经生成，先执行查询不会自动让它用上新结果**，需要将查询结果返回模型再决策。

---

## Q5：★ 长任务怎样控制、澄清和确认结果？

- **控制**：设置轮次、期限、资源预算；重试先区分错误原因和副作用，不盲目重放。
- **澄清**：持久化 `needs_input` 并释放 worker，回复后创建关联运行，不占着 goroutine 等人。
- **确认**：检查客群、预算、真实草案及版本，不能只看最终回答流畅。
- **排障**：同一运行 ID 关联模型与工具耗时、状态、错误和脱敏轨迹。

历史压缩保留目标、边界、关键事实和已执行动作；短期记忆没有统一分钟数。旧偏好只是参考，本次明确要求优先，但不能突破硬约束。

## Q6：★ RAG 的关键链路和常见误区是什么？

```text
解析 → 切片 → Embedding 入库
问题向量化 → 召回片段 → 可选重排 → 带依据生成
```

整篇向量偏向整体语义，不是绝对检索不到细节；切片也不是越小越好，要保留理解所需上下文。

**我的疑问**：“整篇向量可以看成文章概括吗？”可以直观理解，但它不是显式摘要，细节可能被弱化而非完全消失。

召回不足可改写查询并有限重试；耗尽次数只能说“本次依据不足”，不能断言知识库不存在知识，也不能悄悄改成无依据生成。正确片段已召回却生成错，应沿检索、实际上下文、原始输出和后处理定位。

**待核实**：实际模型、参数和个人分工。`bge-reranker-v2-m3` 是本次了解的候选，未实际接入，不能当项目经历。

## Q7：★ Function Calling、MCP、A2A 怎样区分？

| 名称 | 主要解决的问题 |
| --- | --- |
| Function Calling | 模型表达想调用哪个工具、传什么参数 |
| MCP | 应用统一接入工具、资源、提示模板 |
| A2A | 独立 Agent 系统间委托任务、澄清、查询进度与结果 |

工具很多时，由应用按权限和任务筛选，或提供搜索入口，不让模型凭空发现。当前内部仍是静态工具注册表；双 Agent 同进程协作，不是通过 A2A 通信。

---

## Q8：★ 资料与生成代码为什么都不能直接相信？

检索材料夹带指令属于间接提示注入，应当作数据，不能获得执行权限；只写 prompt 不够，还要由后端限制工具与数据访问。

生成代码应在受控环境执行，限制网络、CPU、内存、进程数、输出与执行时间；超时要真正终止。Docker 不是绝对安全隔离。

代码修改后，旧测试不能证明新代码通过。**用代码哈希绑定测试结果与最终版本**；绑定证明版本对应，不证明测试覆盖充分。
