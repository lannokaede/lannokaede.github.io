协议接入与模型决策是两层，工具太多时还需要应用做筛选。

## Q1：MCP 与 Function Calling 有什么关系？

**当时回答**：MCP 给工具加抽象层，解决 M×N 适配；提供 tool、resource、prompt，给工具增加“知识库”。

### A：统一接入的方向对，但三类能力不是工具知识库

| 能力 | 作用 |
| --- | --- |
| Tools | 可调用操作 |
| Resources | 可读取的数据、上下文 |
| Prompts | 可复用的提示模板 |

Function Calling 是模型表达调用意图的方式；MCP 是应用与服务端发现、访问这些能力的协议。应用可以把 MCP 获取的工具定义给模型，收到调用后再通过 MCP 执行。

M×N 是重复适配问题的直观解释，不是说 MCP 自动完成鉴权、业务规则或所有格式转换。

---

## Q2：服务端提供 100 个工具，全交给模型吗？

**当时回答**：不会，模型根据需求找符合描述的工具。

### A：先解释模型怎么知道候选工具

应用先按权限、任务筛选工具，再提供定义；工具特别多时，可以设计受控的工具搜索入口，按需加载。模型看不到任何目录或搜索能力时，不能凭空找出工具。

**我的追问**：“那该怎么说？”

> 先由应用按权限和任务缩小候选，再由模型选择。必要时提供工具搜索能力，减少上下文与选择干扰；执行时仍单独校验权限。

---

## Q3：当前项目实际边界是什么？

内部 Agent 使用静态注册表，不是动态从 MCP 导入工具。对外 MCP 复用四个只读经营工具，不开放保存草案和代码执行能力。不能把工具搜索方案说成已实现。

**复测**：从“发现定义、给模型、模型选择、实际执行”四步标出 MCP 与 Function Calling 各在哪。
