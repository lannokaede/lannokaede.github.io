这次复习最明显的问题是：**能说出技术名词和业务目标，但对执行过程、失败边界和实现细节还不够稳定。** 后续先补这些缺口，不继续无限扩展题目。

## Q：先复习什么？

| 专题 | 优先记住 |
| --- | --- |
| [项目与后端可靠性](/posts/interview/01-backend/) | 取消要接入、事务要提交、幂等不等于重复报错 |
| [Agent 与 RAG](/posts/interview/02-agent-rag/) | 模型提议、后端校验；检索证据和实际经历要讲实 |
| [Redis](/posts/interview/03-redis/) | 原子执行不等于回滚，TTL 不等于淘汰，复制不等于分片 |
| [网络基础](/posts/interview/04-network/) | HTTPS 保护传输；Cookie、Session、Token 各司其职 |

每篇只保留能串起知识的核心 Q&A。**★ 表示当时不会或明显答错，△ 表示容易混淆。** 少量“我的疑问”保留关键思考，不再逐句记录聊天。

## Q：整体进度到哪里了？

**已完成第一遍概念与口述，尚未完成独立复测和编码验证。** 能复述刚讲过的答案，不等于已经掌握。

- **已练过**：项目主流程、任务调度与事务、Agent/RAG、Redis，网络只过基础用途。
- **优先巩固**：事务提交与回滚、幂等作用域、SSE 分片、Redis 原子性与过期、HTTP 身份概念。
- **尚未深入**：织课的 OnlyOffice/MinIO/版本管理与并发请求合并，测试设计、真实排障和个人分工。
- **暂缓**：按个人安排先不练 Go 语言基础和 SQL；算法、手写代码也尚未验证。
- **待核实**：织课实际模型、切分参数和本人分工；重排只是学习过的方案，不能说成已经接入。

每次遮住答案口述两三题，讲清“为什么、怎么执行、失败后怎样”，答不出的再回看。同一缺口确认后就切换主题，不把模拟变成连续重复教学。
