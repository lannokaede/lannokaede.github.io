> **复习标记：重点不会** · 本文按真实模拟对话整理。“当时回答”与“我的追问”为原话摘录或明确标注的归纳；参考答案是整理后的解释，不表示已独立掌握。

从模型生成调用到后端真正执行，区分调用 ID、工具名和可信业务约束。

## Q1：模型怎样知道有哪些工具？

**当时回答**：“有结构化描述，模型知道工具和功能。”

### A：还包括参数结构，后端负责分发和执行

模型可能返回类似内容，字段仅作示例：

```json
{
  "id": "call_123",
  "function": {
    "name": "preview_customer_segment",
    "arguments": "{\"inactive_days\":60}"
  }
}
```

`id` 关联本次调用和返回结果；`name` 用来查找预先注册的处理函数；`arguments` 需要解析和校验。模型不是直接执行 Go 函数。

**当时误区**：只回答“返回工具 id”，不清楚怎样找到 Go 函数。

---

## Q2：JSON 合法、类型正确，就能执行吗？

**当时回答**：需要检查用户有没有权限，普通用户不能读后台敏感信息。

### A：还要检查归属与业务约束

身份由后端可信凭证确定，不相信模型传入的用户身份。检查工具白名单、数据归属、参数取值、预算与当前业务状态。未知工具或非法参数应拒绝，不动态执行任意函数名、命令。

---

## Q3：预算强制检查怎样做？

**我的追问**：“预算也就是单独的一个字段才好检查吧？”

### A：关键是可信结构化数据与必经校验

后端把 3000 元转成 `300000` 分，校验后随任务保存。worker 读取可信预算，工具根据模型提交的数量、面额计算最大优惠责任，并校验正数与整数溢出。模型不能通过提交“预算变成 5000”修改这份约束。

```text
模型：200 张 × 20 元 = 4000 元
后端任务预算：3000 元
保存工具：拒绝写入，返回超预算错误
```

自然语言里提到预算，不自动等于已建立硬约束；项目独立上限大于 0 才启用额外运行预算限制。

---

## Q4：除了单独字段，还有更好的方案吗？

**我的追问**：“除了这种应该没有更好的方案了吧？”

### A：输入方式可变，但执行约束不能只交给模型

可以从自然语言提取并请用户确认，也可以从商家配置、审批记录读取。多个活动共用总预算时，还需要共享预算的原子预占与释放，不能只做单次上限校验。

这些是可选设计，不能描述为当前项目全部实现。

---

## Q5：跳过试算，直接保存超预算草案怎么办？

保存时仍重新校验，拒绝超限写入，把错误返回模型。模型可能修正，也可能继续犯错；轮次和时间上限负责终止，不保证下一轮一定先试算。

**复测**：按“声明 → 模型调用 → 后端分发 → 校验 → 执行 → 结果回传”讲一遍，说明每一步谁负责。
